Architecture · Protocol V2 + Mesh · ForwardMesh

Self-learning cross-subnet file forwarding mesh

Nodes passively learn reachable peers from transit traffic, reconcile loop-free path vectors over periodic heartbeats, auto-complete omitted intermediate hops, and reroute around mid-path failures while streaming 64 KB CRC32-verified chunks.

MESH CONTROL PLANE

Path-vector learning & auto-failover

  • Zero-config passive route learning from transit traffic, persisted atomically to <dir>/mesh_routes.dat
  • Periodic ForwardMeshSync (cmd=2) (-I 3000ms) and cache-miss sync stitch multi-subnet routes with IsSelf loop eviction
  • Auto-completes omitted hops (fwd -a N1,N3) and reroutes around dead hops unless strict -R is set; inspect via fwd -l

DATA PLANE & PROTOCOL V2

Cut-through streaming & 64-bit frame

  • Big-endian frame: ForwardHead (28B) + ForwardNode[ttl] + ForwardFile + data (uint64_t length lifts 4 GB limit)
  • RelayStream() pipes 64 KB buffers with zero intermediate disk writes, or tees to .fwd_tee_XXXXXX on -s / -S
  • flags[2..7] tracks physical hops_traversed to enforce a hard 32-hop ceiling against static loops

INTEGRITY & DAEMON OPS

In-flight CRC32 & elastic pool

  • IEEE 802.3 crc32 verified on hops, endpoints, and sync payloads before atomic rename() (retcode = 6 on tamper)
  • Pre-fork() bind, poll() accept + elastic worker pool (-t 4..64), non-blocking timeout dialer, and -F / -P lifecycle
  • Working-directory path sandbox (IsSafeRelativePath) and 64-bit request id correlation across logs
